# Расширенный дизайн Startup Team

21 октября 2026. Визуальная основа — исходный `final.html` из коммита `1762b45`. Все 57 файлов этого коммита сохранены без изменений. Продолжение находится отдельно: `prototypes/complete.html`, `prototypes/src/complete/`.

## Открыть

```bash
docker compose -p startup_team_design_complete -f design/compose.complete.yaml up -d --build
```

Из корня проекта. Адрес: http://127.0.0.1:18084/complete.html.

Остановить только дизайн:

```bash
docker compose -p startup_team_design_complete -f design/compose.complete.yaml down
```

API, основная база и Docker-тома приложения не используются. Порт меняется через `COMPLETE_DESIGN_PORT`. Для запуска через Vite: из `design/prototypes` выполнить `npm ci`, затем `npm run dev` и открыть `/complete.html`. Отдельная production-сборка: `npx tsc --noEmit && npx vite build --config vite.complete.config.ts`.

## Границы

Это **дизайн-прототип**, не интегрированный frontend. Он не вызывает API, не проверяет Telegram initData, не регистрирует серверных пользователей и не доставляет внешние уведомления. Данные вымышлены, сохраняются в localStorage с отдельным ключом `startup-team-complete-design-v1`. Уведомления в прототипе общие, а не приватная адресная доставка. Условные права, ёмкость, проверки сроков и переходы не заменяют серверные инварианты. Все эти правила при интеграции должны остаться за существующим backend.

Тёмная тема, Manrope, бренд, сетки и примитивы взяты из `src/final/`; новые стили расширяют их. В мобильных формах шрифт 16 px; предусмотрены отступы safe-area для dialog, но настоящая Telegram content-safe-area/viewport/BackButton-интеграция ещё не выполнялась. Полный межбраузерный и screen-reader аудит не заявляется.

## Исправления перед независимым ревью

Правила вынесены в `src/complete/rules.ts`. Сброс не отменяет ожидающие приглашения; их условия берутся из версии попытки. Решения добавляются отдельными записями с попыткой и версией тестового; критическое изменение не затрагивает завершённые наймы. Членства и места связаны с ID вакансии. Добавлены срок рекрутерского приглашения, поиск участника, автоматическое истечение, дата со временем, удаление пустого проекта и проверки формы с сохранением ввода при ошибке. Новая попытка после выхода сохраняет старые факты вступления.

Прежний ключ localStorage сохранён. Доступные старые ссылки восстанавливаются из записанных событий и последнего решения. Неизвестная привязка к попытке/вакансии явно отмечается, а не выдумывается; потерянные раньше сведения восстановить невозможно. Старое рекрутерское приглашение без срока требует нового приглашения. Ограничение мест не уменьшается при неизвестной старой привязке, отправка нового offer в таком проекте блокируется до проверки данных.

Docker-сборка дополнительно выполняет 47 проверок правил и разметки истории на изолированных демоданных (`invariants.ts`). Это проверки прототипа, не серверной безопасности. Исторический отчёт: `docs/DESIGN_FIXES_2026-10-21.md`. Промт для отдельного ревью: `docs/INDEPENDENT_REVIEW_PROMPT_2026-10-21.md`.

## Второй этап: F2/F6, завершён 22 октября 2026

Для каждой пары «попытка / версия тестового» допускается одно решение, как в API. Повторная команда отклоняется без изменения ссылки и событий; другая допустимая версия или новая попытка позволяют отдельную сдачу. Форма показывает только доступные версии, скрывает кнопку при их отсутствии и объясняет ограничение. Прежняя кнопка «Отправить другое решение» удалена. Ранее сохранённые демозаписи не удаляются.

Кандидатская история показывает название роли, описание и требования версии каждой попытки, её письмо и причину решения. Заголовок отклика использует версию текущей попытки, а не сегодняшнее название вакансии. Если старые условия отсутствуют, интерфейс сообщает об этом и не подставляет новые. Общий отклик явно показан без привязки к вакансии.
