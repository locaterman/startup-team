## Что проверить сначала

- Полный путь двух пользователей: вход → публикация → отклик → полученные заявки → решение → результат в кабинете. Проверить реальные HTTP и UI, не только наличие кнопок/маршрутов.
- Все сочетания статических и динамических routes; сравнить целевой и фактический OpenAPI, валидацию, ответы, ошибки и повторные команды.
- Матрица прав: посторонний, кандидат, обычный участник, внешний рекрутер, владелец; пользователь одновременно в нескольких отношениях. Негативные прямые API-запросы, self-review и отзыв grants.
- PostgreSQL: связи разных кандидатов/стартапов/версий, неизменяемость истории, переходы Offer/Attempt/Membership и общий отклик без vacancy capacity.
- Независимые сроки intake/offer/test, pause/archive; архив не означает выход участников.
- Конкурентные запросы через отдельные соединения с управляемой синхронизацией: два рекрутера на последнее место; accept/revoke; accept/archive; accept/expiry; reset/resubmit; vacancy version/apply; grant revoke/edit; leave/new offer.
- Upgrade существующей схемы с данными, сохранение после restart, чистый Docker build. Успешная initial migration не доказывает upgrade.
- Доступность всех согласованных функций через UI, пустые состояния, связи с названиями проекта/вакансии/кандидата, ошибки сети, mobile overflow и клавиатура.

Каждая находка: категория расхождения, BLOCKER/MAJOR/MINOR/IMPROVEMENT, CONFIRMED/INFERRED/ASSUMED/UNVERIFIED/BLOCKED, инвариант, файл/строка, минимальное воспроизведение, ожидаемое и фактическое поведение, последствия, минимальное направление исправления, критерий проверки. Отделяй вкусовые предпочтения от дефектов. Не считай двадцать известных инвариантов исчерпывающими.

## Работа с окружением

- Папка сейчас без `.git`; не придумывай branch/commit. Для сверки исходников есть `docs/audit/source_sha256.json`.
- Проект основного запуска имеет имя `startup_team_demo_macos`; контейнеры были Paused. Не очищай volume, не запускай тестовые TRUNCATE в основной БД, не делай down -v.
- `docs/audit/run_isolated_postgres.py` запускает два существующих DB-теста с актуальными исходниками на отдельной PostgreSQL 16 в tmpfs, без сети наружу и портов. Использует локальные образы. Это вспомогательный безопасный способ воспроизведения, не замена собственным тестам.
- Новые тесты/эксперименты делай в явно изолированной базе; новые выводы не требуют изменения приложения в процессе аудита.
- Не делай push/публикацию и не отправляй сообщения другим чатам без поручения пользователя. Передай отчёт пользователю для сопоставления результатов.

Результат: приоритетный список воспроизводимых дефектов, отдельно спорные продуктовые решения и непроверенные риски, перечень исполненных команд/тестов с их пределами. Аудит можно завершить, когда исчерпаны содержательные проверки и оставшиеся неопределённости явно отмечены; новые функции ради аудита не добавляй.
