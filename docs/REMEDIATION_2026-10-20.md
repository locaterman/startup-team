## Оценка выводов

Содержательные замечания приняты с указанными ревьюером границами доказательства. Оснований отвергать отчёт или переписывать весь монолит нет. Особенно важно сохранить различие между нарушением через API и произвольным SQL администратора: A09 не доказывает доступный пользователю обход capacity. Проверенные конкурентные запросы выдержали основной протокол блокировки строки стартапа.

`50 passed` исходного ревью — исторический результат измерений, многие из которых утверждают ошибочное поведение. Исходные пробы, runner, результаты и baseline SHA-манифест сохранены без изменений. После исправления старые defect assertions закономерно перестанут проходить. Вместо изменения их смысла добавлен отдельный штатный регрессионный модуль `backend/tests/test_remediation_postgres.py`.

## Browser E2E

Отдельный стенд `startup_remediation_20261020` на `127.0.0.1:18081`, новая тестовая PostgreSQL в tmpfs, актуальные backend-исходники readonly, отдельно собранный исправленный frontend. Основной и ревьюерский стенды не переиспользовались.

Всё ниже выполнено через элементы интерфейса, без подстановки application/offer через SQL/HTTP:

1. Иван вошёл и создал стартап «Проверка исправлений».
2. Создал вакансию «Python — проверка сценария» с одним местом.
3. Вышел, вошла Мария; нашла вакансию и отправила текст через новую форму.
4. Кабинет Марии показал один отклик со статусом «Новый».
5. Иван вошёл, увидел входящий отклик, перевёл на рассмотрение и отправил приглашение.
6. Мария вошла, увидела invitation и приняла.
7. В кабинете отображаются «В команде» для отклика и «Принято» для приглашения, ошибки нет.

Скриншот: `docs/audit/remediation/cabinet-joined.png`.

После проверки собственный одноразовый UI-стенд остановлен и удалён командой `down` только для проекта `startup_remediation_20261020`. Основные и ревьюерские контейнеры не изменялись. Изменения исходников не развёрнуты в основном приложении; ему потребуется отдельная пересборка frontend/API.

Отказ, disabled network, panel failure injection, mobile/keyboard и полная историческая навигация в этом browser walkthrough не проверялись. API-регрессии отдельно проверяют запрещённый self-revoke и допустимые кандидатские accept/decline. Нельзя превращать этот позитивный E2E в утверждение о готовности всех экранов.
