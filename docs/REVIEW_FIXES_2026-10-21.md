# Исправления первого этапа — 21 октября 2026

Поручение: закрыть F1/F4/F5 последнего adversarial-ревью и обеспечить обязательность первого заполнения Telegram-профиля на сервере (F3). Исправления сделаны в рабочей копии. Исходный отчёт и его контрпримеры оставлены как историческое свидетельство; старые probes проверяют наличие ошибок, поэтому их нельзя считать актуальными acceptance-тестами после исправлений.

## Изменения

- **F1:** restore под блокировкой стартапа сверяет решения конкретной восстанавливаемой попытки с последующими critical-версиями. Устаревшие решения получают `superseded`; `reviewed_by`, `reviewed_at`, события и сами ссылки сохраняются. Ordinary не инвалидирует решение. Завершённые наймы и другие исторические попытки restore не меняет.
- **F3:** dependency `domain_auth` применяется к 30 обработчикам доменных команд. Новая Telegram-учётная запись без завершённого профиля получает `403 ONBOARDING_REQUIRED`. Чтение, auth/context/csrf/logout и PATCH своего профиля доступны. Явное валидное имя завершает onboarding; сохранение одного bio не завершает. Демо-пользователи работают как прежде. UI получил понятный текст новой ошибки; контракт описывает правило.
- **F4:** create/settings принимают строгое целое число мест в диапазоне 1..2147483647. Переполнение, строка, bool и дробь возвращают 422 в существующем Error envelope до записи. OpenAPI и его генератор согласованы с границами PostgreSQL.
- **F5:** оба списка приглашений используют вычисляемый статус по времени БД: просроченный pending отображается как expired. Поздний accept не выдаёт grant; последующий owner read не нужен. Приглашение можно повторить после истечения. Поздний revoke отклоняется; archive сначала фиксирует истечение, затем отзывает оставшиеся pending, чтобы expired не превращался в revoked.

Изменения не требуют новой схемы БД. Рабочий Compose и его данные не использовались для тестов и не пересоздавались. Ранее восстановленные активные попытки не исправляются массовой миграцией: новое правило выполняется при restore. Макет complete на этом этапе не менялся; F2/F6 остаются следующей работой.

## Повторение

Требуется Docker Desktop и локальный образ зависимостей `startup-adversarial-api:20261021`. Если образа нет, собрать из проекта:

```sh
docker build -f backend/Dockerfile -t startup-adversarial-api:20261021 .
python3 tools/verify_review_fixes.py
```

Runner монтирует текущие исходники readonly, применяет миграции только к случайно названной временной PostgreSQL в tmpfs, без опубликованных портов и внешней сети; удаляет собственный контейнер в finally. Основной Compose не вызывается. Логи сохраняются в отдельный каталог этого этапа. Для проверки только новых PostgreSQL-регрессий: `python3 tools/verify_review_fixes.py --regressions-only`.
