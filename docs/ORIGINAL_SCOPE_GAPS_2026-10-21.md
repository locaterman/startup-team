# Первоначальный замысел: что ещё отсутствует

21 октября 2026. Сверка мастер-промпта с рабочим приложением и отдельным complete-дизайном. Это анализ исходников; новые runtime/DB-тесты в этом проходе не выполнялись.

Обновление после этой сверки: по поручению пользователя реализованы серверная проверка initData, Telegram-only аккаунты, сессии и реальный onboarding. См. [TELEGRAM_SETUP.md](TELEGRAM_SETUP.md). Ниже сохранён срез до этих изменений: пункты о полностью отсутствующем серверном Telegram-входе уже частично закрыты; настоящий бот, сервер и Telegram WebView ещё не проверены.

Обновление после исправлений прототипа: перечисленные ниже ошибки complete-дизайна относятся к предыдущему срезу. Теперь добавлены история решений по попыткам/версиям, сохранение приглашений при сбросе, снимки условий попытки, учёт мест по ID вакансии, сроки и поиск рекрутеров, время в формах и удаление пустого проекта. Подробности и границы проверки: [DESIGN_FIXES_2026-10-21.md](DESIGN_FIXES_2026-10-21.md). Подключение complete к API по-прежнему не выполнено.

## Источник и три разных состояния

Источник замысла — пользовательский мастер-промпт в приложении `d69c21d8-735a-4f53-886b-b7b527b31a62/Вставленный текст.txt`. Исходный DOCX по-прежнему отсутствует, поэтому официальные требования известны по пересказу. В нём отдельно зафиксированы обязательный веб-прототип, согласованные 12 групп функций и дополнительные будущие возможности.

- Рабочее приложение: `frontend/src/`, `backend/app/`, PostgreSQL, Compose. Вход в заранее созданные аккаунты.
- Выбранная визуальная основа: исходный `design/prototypes/final.html`, коммит `1762b45`.
- Продолжение дизайна: `design/prototypes/complete.html`, `src/complete/`. Демо в localStorage, без API; исходники пока не закоммичены. Не является заменой рабочему приложению.

## Проверка 12 согласованных групп

| Группа | Рабочее приложение | Новый complete-дизайн |
|---|---|---|
| Профиль, тестовая авторизация, кабинет | Есть | Экраны и локальный выбор пользователя; серверный вход не подключён |
| Создание/просмотр нескольких стартапов | Есть | Есть демоформы |
| Много вакансий внутри стартапа | Есть | Есть демоформы и отдельный каталог |
| Общие и вакансионные отклики | Есть | Есть локальные сценарии |
| Разрешение общих откликов | Есть | Есть переключатель |
| Рассмотрение, отказ, положительное решение | Есть, с отдельным Offer и согласием кандидата | Есть визуальные сценарии, упрощённые переходы |
| Дубли, чужие действия, роли | Серверные проверки, ограничения и транзакции реализованы; исторические проверки описаны в COMPLETION | Отдельной серверной защиты нет; демоограничения не доказывают безопасность |
| Закрытие/архив и сохранение истории | Есть | Основные экраны есть; отдельные правила и история упрощены |
| Приглашения/резервирование/согласие | Есть | Сценарий есть, резервы не являются достоверной моделью |
| Рекрутеры и команды | Есть | Основные экраны есть; поиск/срок рекрутерского приглашения не доведены |
| Версии тестовых/решений | Есть | Формы есть; хранение решений и критические изменения расходятся с замыслом |
| Версии вакансий/массовый сброс | Есть | Формы есть; правило ожидающих приглашений ошибочно изменено |

Следовательно, нет основания объявлять какую-либо из этих групп полностью отсутствующей в рабочем backend. Главный незавершённый слой — соединение новой визуальной системы с существующими рабочими сценариями и точное покрытие правил в интерфейсе.

## Отсутствующие части продукта

1. **Интегрированный новый интерфейс.** Основной frontend по-прежнему старый. Новый дизайн живёт отдельно, не читает PostgreSQL, не вызывает API, не использует серверные сессии, CSRF, revision guards и квитанции команд.
2. **Настоящий Telegram Mini App.** Нет SDK/инициализации, серверной проверки initData, привязки Telegram ID, настроенного запуска через бота, Telegram BackButton/viewport/content-safe-area интеграции и проверки в реальном Telegram iOS/Android.
3. **Подключение новых участников.** В backend есть login/logout/me/csrf, но нет самостоятельного создания аккаунта. Демо-кнопка создания профиля в complete не создаёт пользователя в PostgreSQL. Для будущего Telegram-режима нужен первый подтверждённый вход с созданием/привязкой профиля. Email-регистрация, подтверждение email и восстановление пароля также отсутствуют; это отдельный способ входа, не явно включённый в исходные 12 групп.
4. **Проверенное размещение для реальных участников.** В репозитории есть локальный loopback Compose. Публичный HTTPS-стенд, рабочая конфигурация секретов и эксплуатация с восстановлением из backup не подтверждены. Наличие локальной копии базы не доказывает успешное восстановление.
5. **Внешняя доставка уведомлений.** Внутренние уведомления существуют в рабочем приложении. Telegram/email-доставки нет. По мастер-промпту она не требовалась в первой версии; для Telegram-продукта это отдельный следующий шаг.

Telegram и внешняя доставка не являлись обязательным условием первой демоверсии по сохранённому мастер-промпту. При этом они действительно отсутствуют относительно будущего продукта внутри Telegram, о котором говорит пользователь.

## Конкретные пробелы и расхождения нового дизайна

Все пункты ниже подтверждены чтением кода complete; они не являются найденными заново дефектами рабочего backend. Предыдущая формулировка «дизайн доделан» была слишком широкой: оформлены основные экраны, но не все правила и частные состояния.

| Проблема | Первоначальное правило | Что сейчас в прототипе |
|---|---|---|
| Сброс отменяет приглашения | Мастер §5.10: ожидающие Offer сохраняются на прежних условиях; отдельный отзыв менеджером | `versionForm` включает offer_pending в reset, ставит pending Offer в revoked и обещает это в тексте формы. Backend `new_version` правильно исключает offer_pending |
| Критическое тестовое затрагивает завершённые наймы | §5.9: обновление касается незавершённых процессов | `taskForm` помечает superseded все записи с solution, без фильтра состояния заявки |
| Нет полноценного списка исторических решений | §5.9/5.10: решения конкретных версий и попыток сохраняются | В Entry одно поле solution/testVersion/testStatus, новое решение перезаписывает его. Ссылки остаются в тексте событий, но отдельной истории Submission нет |
| Условия приглашения берутся из текущей вакансии | §5.6/5.10: Offer привязан к конкретной попытке и её условиям | `invite` использует текущие title/description/versions.length Vacancy; при keep_applications это может быть другая версия, чем у отклика |
| Места связаны с названием роли | §5.7: занятое место привязано к исходной вакансии | `vacancyDetails` считает members по `role === v.title`. Переименование/одинаковые названия дают неверную картину |
| Рекрутерское приглашение без даты и поиска | §5.8; рабочий UI поддерживает поиск и срок | Выбор из демосписка, у Recruiter нет expires_at; нужны макет поиска, срок и истёкшее/отозванное приглашение |
| Точность сроков | В backend datetime и независимые intake/offer/test deadlines | Новые формы содержат date, без времени; при подключении нельзя молча терять время и часовой пояс |
| Удаление проекта без взаимодействий | §5.2: обсуждалось удаление, иначе архив | Backend DELETE `/startups/{id}` существует; кнопки нет в рабочем frontend и complete. Правило дополнительно обсуждалось, не выделено отдельным пунктом Scope Freeze |
| Повторная подача после выхода | §5.5: старое joined не переписывается, новая попытка отдельная; backend также поддерживает already_joined | В complete нет отдельного полного состояния такой истории; конкурирующие заявки сводятся в closed. Нужна точная визуальная карта терминальных исходов |
| Защита/ошибки в новом UI | Реальные ошибки доступа, сети, конфликта и повтора | Есть отдельные демонстрационные макеты ошибок, но они ещё не связаны с настоящими запросами и состояниями команд |

Эти места исправлять в прототипе/адаптерах, сохраняя существующую бизнес-логику, а не менять backend под упрощённую модель макета.

## Что не является забытым обязательством

- AI-подбор, рекомендации, рейтинги, ранжирование, сложный matching явно отложены в Scope Freeze.
- Чат, платежи, загрузка файлов и полноценное HR-резюме не входят в согласованные 12 групп. Тестовые принимаются HTTPS-ссылкой.
- «Интересы» профиля перечислены среди предварительно обсуждавшихся полей, но отдельным обязательным полем не зафиксированы. В рабочем профиле есть bio, skills и portfolio_url.
- SQL-side keyset и сохранение ключа повторной команды после reload — известные инженерные улучшения, а не новые продуктовые разделы. Текущая пагинация функциональна, ключ команды живёт в памяти страницы.

## Сдача и проверка

Остаются независимое ревью актуального состояния, новый сквозной прогон после интеграции дизайна, воспроизведение из чистого клона, сверка с DOCX, реальное время и личный пример самостоятельной проверки AI. Публичный репозиторий указан в пересказе ТЗ; текущий репозиторий приватный по последнему запросу пользователя — видимость самостоятельно не менять. Новые материалы дизайна пока локальные, их ещё нужно сохранить в Git и загрузить перед удалённым ревью.

Приоритет: устранить найденные расхождения прототипа → независимое ревью → интегрировать новый UI с сохранением всех сценариев → реальный первый вход/Telegram/размещение в согласованном объёме → финальная проверка и сдача. Это план, изменения приложения в ходе этой сверки не выполнялись.
