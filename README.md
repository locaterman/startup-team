# Startup Team — тестовое задание AI-native разработчика

Локальный адаптивный веб-прототип модуля стартапов Бизнес-клуба. Участники публикуют проекты и вакансии, откликаются, рассматривают кандидатов и формируют команды. Один пользователь может одновременно владеть проектами, быть кандидатом, участником команды и внешним рекрутером.

Контекст продукта — будущий Telegram Mini App; эта версия работает как самостоятельный веб-интерфейс. Telegram initData, AI-подбор, рейтинги и рекомендации не реализованы.

## Запуск на macOS, Linux и Windows

Нужен Docker с Compose v2. Если вы обновляете существующий запуск с данными, сначала прочитайте раздел о миграциях и сделайте резервную копию. Из корня проекта:

```bash
cp -n .env.example .env
docker compose -p startup_team_demo_macos up --build -d
docker compose -p startup_team_demo_macos logs -f api
```

Дождитесь завершения миграций и запуска Uvicorn. Откройте http://127.0.0.1:8080. Порт меняется через WEB_PORT в .env. Сервер доступен только на loopback; основной том PostgreSQL сохраняется при обычном down.

На Windows скопируйте `.env.example` в `.env` средствами PowerShell или проводника, затем используйте те же команды Docker.

| Пользователь | Email | Пароль |
|---|---|---|
| Иван | ivan@example.test | demo-ivan-123 |
| Мария | maria@example.test | demo-maria-123 |
| Алекс | alex@example.test | demo-alex-123 |

Это локальные вымышленные аккаунты. Для публичного размещения нужны отдельные безопасные учётные данные, секреты и HTTPS; текущая демо-конфигурация для этого не предназначена.

Остановить приложение, сохранив данные:

```bash
docker compose -p startup_team_demo_macos down
```

Не добавляйте `-v`, если данные нужно сохранить.

## Возможности

- Профиль: имя, описание, навыки, портфолио; серверные сессии и CSRF.
- Каталог стартапов и вакансий со страницами и подробными условиями.
- Общие и вакансионные отклики, просмотр результатов, отзыв и восстановление.
- Кабинет собственных/управляемых проектов независимо от публичной ленты; закрытые проекты не исчезают.
- Пауза и архив стартапа; настройка общих откликов.
- Места, срок приёма, закрытие/возобновление и архив вакансии.
- Новые версии условий, сохранение либо сброс текущих откликов, новая попытка после сброса или выхода из команды.
- Приглашения с сообщением, сроком и точными историческими условиями; принятие/отказ кандидата и отзыв менеджером.
- Членство, выход и исключение с сохранением истории; рекрутерские полномочия существуют отдельно.
- Поиск участника по имени, приглашение внешнего рекрутера, принятие и отзыв прав.
- Версии опциональных тестовых заданий, HTTPS-решения конкретной версии, критические изменения и отметка проверки.
- Старые письма и условия, причины решений и связанные события доступны участникам соответствующего процесса.
- Адресные внутренние уведомления о ключевых событиях: отклики, решения, приглашения, тестовые и изменения условий. Email/Telegram-доставки нет.

## Основной сценарий демонстрации

1. Иван создаёт стартап и вакансию.
2. Мария входит, находит вакансию, отправляет отклик.
3. Иван видит заявку в кабинете, отклоняет с причиной либо отправляет приглашение.
4. Мария видит решение. Принятие приглашения создаёт членство только с её согласия.
5. Дополнительно: Иван меняет условия со сбросом; Мария подаёт новую попытку и видит старое письмо в истории.

## Архитектура и правила

Python 3.12 / FastAPI / SQLAlchemy Core / PostgreSQL 16 / Alembic. React 19 / TypeScript / Vite, Nginx, Docker Compose. Монолит сохраняет связанные действия в одной PostgreSQL-транзакции.

Application хранит постоянную связь человека с предложением; ApplicationAttempt — отдельную историческую подачу. Offer привязан к конкретной попытке и версии условий. Membership появляется после согласия кандидата. RecruiterGrant не даёт членство и не возникает из членства.

Дедлайн вакансии прекращает новые отклики, но не рассмотрение. Ожидающее приглашение резервирует место. Все capacity-операции используют блокировку строки стартапа. Архив стартапа завершает набор, сохраняя участников и историю. Архив вакансии сохраняет ранее отправленные приглашения.

Контракт: [contracts/openapi.yaml](contracts/openapi.yaml), генератор: [tools/generate_contract.py](tools/generate_contract.py). Правила: [docs/STATE_MACHINES.md](docs/STATE_MACHINES.md). Наличие маршрута само по себе не доказывает его поведение.

## Повторы, ревизии и страницы

Все авторизованные команды поддерживают необязательный `Idempotency-Key` (8–120 букв/цифр или ._:-). Один actor/key распознаётся во всех маршрутах. Путь, нормализованное содержимое и If-Match входят в fingerprint. Успешный результат сохраняется атомарно с действием; повтор возвращает тот же результат, другое содержимое — 409. Ошибки не кэшируются. Квитанции хранятся в БД без автоматического истечения.

UI повторно использует ключ после сетевой ошибки в открытой сессии страницы. После перезагрузки страницы автоматическое восстановление незавершённого запроса не реализовано: проверьте результат в истории прежде, чем заново запускать массовое действие. Прямой API-клиент должен сохранять и повторять исходный ключ самостоятельно. Без ключа POST считается новой командой.

Изменения объектов поддерживают `If-Match: "N"`, где N — полученная revision. Устаревшая ревизия даёт 409. Replay сохранённого результата проверяется до ревизии, поэтому уже выполненная команда не запускается снова на новых данных. Сессия и CSRF проверяются при каждом запросе.

Списки принимают limit 1–100 (по умолчанию 20), cursor и возвращают next_cursor. Курсор подписан и привязан к пользователю, пути и фильтрам. Порядок — UUID по возрастанию; новые записи перед текущей позицией видны после обновления. UI загружает следующие страницы каталога; кабинет собирает все доступные ему страницы.

Ограничение масштаба прототипа: сервер сначала материализует разрешённую выборку, затем формирует страницу. Это устраняет потерю записей за первой сотней, но не является оптимизацией для больших каталогов. При росте объёма следует перенести ту же keyset-фильтрацию в SQL.

## Миграции и существующие данные

`0001_initial` теперь читает зафиксированный `0001_schema.sql` рядом с миграцией. Изменение рабочего initial SQL больше не меняет её смысл. `0002_integrity_history` отдельно проверяет связи и ёмкость, устанавливает ограничения и добавляет причину отказа. Противоречивые старые записи останавливают обновление; они не удаляются автоматически. Миграция forward-only: откат — из проверенной резервной копии.

Проверены чистая установка, обновление совместимой схемы без триггеров, отказ на противоречивых данных и обновление точной schema-only копии существующей локальной БД с синтетическими данными. Основная БД при этих тестах не обновлялась. Перед её обновлением необходима резервная копия. Это не заявление о проверке всех исторических вариантов v0.1.

## Проверки

На Mac:

```bash
bash tools/test_on_macos.sh
```

На Linux: `bash tools/test_on_linux.sh`. На Windows: `powershell -ExecutionPolicy Bypass -File tools/test_on_windows.ps1`.

Скрипты запускают приложение и тесты в отдельной случайно названной PostgreSQL-базе. Fixtures очищают тестовые таблицы; не направляйте TEST_DATABASE_URL на рабочую базу. Для повторения расширенного протокола с существующими локальными образами: `python3 docs/audit/completion/run.py`.

Актуальные результаты и пределы проверки: [docs/COMPLETION_2026-10-20.md](docs/COMPLETION_2026-10-20.md). Старые baseline и материалы ревью сохранены как исторические свидетельства, а не описание текущей версии.

## Использование AI

AI использован для анализа требований, сравнения архитектурных вариантов, реализации API/UI, подготовки миграций и тестов, поиска контрпримеров и технической документации. Предложения проверялись на PostgreSQL, негативными запросами, управляемой конкуренцией, JSON Schema и браузерными сценариями. Независимый ревьюер нашёл дефекты, которые штатные тесты не обнаруживали; исправления получили отдельные регрессии.
